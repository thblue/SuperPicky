# 定星与去重规则补充说明 / Rating & Dedup Rules Supplement

> 适用版本：4.5.0 + `my-mods` 分支提交 `b68e02e`、`97a1387`（2026-08）。
> 本文是对 V2 配额定星与相似去重的**行为补充文档**，便于日后查找"为什么这张照片是这个星级"。

## 一、V2 定星全流程（执行顺序） / V2 Rating Pipeline

1. **硬门槛**（`core/rating_quota.py::gate_photo`）——任一命中直接出局，不进配额池：
   - 没检测到鸟 → -1（无鸟）
   - YOLO 置信度 < 0.50 → 0
   - 归一化锐度 < 100 → 0
   - TOPIQ 美学分 < 3.5 → 0
   - 眼/喙关键点全不可见 → 1
2. **综合分 Q**（`compute_q`）：
   `Q = 0.65 × 锐度批内百分位 + 0.35 × TOPIQ 批内百分位`
   微调：飞行 +0.06、精焦 +0.04、脱焦 −0.06、曝光问题 −0.06。
   百分位在**本批（同一目录、同一次处理）过门槛的全部照片**里计算，是相对分。
3. **按鸟种切配额**（`assign_ratings`）：
   - 照片按鸟种分组，组内按 Q 降序；
   - 每组 3★ = `ceil(张数 × quota3%)`，2★ = `ceil(张数 × quota2%)`
     （配额由技能等级决定，custom 模式读 `advanced_config.json` 的
     `custom_quota3` / `custom_quota2`）；
   - 3★ 绝对锐度兜底：排进 3★ 档但锐度 < 300 → 降 2★；
   - 眼睛可见度 < 0.5 → 封顶 2★；
   - 小样本鸟种天然保底最好的 1 张 3★（前提是过兜底/封顶约束）；
   - 未开识鸟或未识别 → 单组，退化为全局配额。
4. **连拍/相似簇封顶**（见下节）。

V1（`core/rating_engine.py`，绝对阈值模式）不含鸟种配额与封顶逻辑。

## 二、连拍/相似簇封顶规则 / Burst & Similarity-Cluster Cap

**规则（`rating_quota.py` 尾部，`burst_cap3` 默认 2）：**

| 组内情况 | 结果 |
|---|---|
| 组内有 3★ | 只保留 3★ 本身（至多 2 张），**其余一律 1★（含原 2★）** |
| 组内无 3★ | 保 Q 最高的前 2 张维持配额星级，其余 1★（不强行拔高到 3★） |

设计意图：严控 2★/3★ 为"稀有鸟种 + 各鸟种最优"；同组照片互为替品，
人工 review 与鸟种统计只需关注 ≥2★，1★ 有错也不影响结论。

**组的两个来源：**

1. **EXIF 时间连拍**（`core/burst_detector.py`）：相邻照片时间差
   ≤ `burst_time_threshold`（默认 250ms）且组内 ≥ 4 张；pHash 验证剔除误判。
2. **pHash 相似簇**（`cluster_similar_by_phash`，跨时段）：
   - 只在**同鸟种**内两两比较 pHash 汉明距离，≤ `PHASH_SIM_THRESHOLD`（=12）
     判相似，并查集传递闭包成簇；
   - 只处理**不在时间连拍组**里的配额池照片；
   - 输入图片用 `.superpicky/cache/temp_preview/<前缀>.jpg` 预览图
     （RAW 本体 PIL 不可解码）；
   - 伪 burst_id 接在真实连拍组 id 之后，**不写入 burst_map**：
     只影响打星，不触发连拍子目录移动；
   - **不持久化**：簇信息只在定星时使用，report.db / sidecar JSON 里
     `burst_id` 为空，无法事后追溯分组。
   - 阈值 12 的校准依据：867 张水鸟批实测，同鸟种照片对距离中位 ~30、
     p5 ~24；阈值 8 几乎聚不出簇，12 可聚 ~65 组且确有高星冗余。
     若发现不同姿态被误并（簇内 3★ 被压掉）→ 调小；雷同照仍各自高星 → 调大。

## 三、非破坏工作流（JSON sidecar） / Non-Destructive Workflow

`core/sidecar_export.py` 在批处理结束时把 report.db 导出为每照片一份 JSON：
`.superpicky/meta/<前缀>.json`（UTF-8，含星级/鸟种/检测框/稀有度/edits）。
配合 CLI 可实现"不动文件、只出数据"：

```bash
.venv/Scripts/python.exe superpicky_cli.py process <目录> \
    --no-organize --metadata-mode none --auto-identify --burst
```

- `--no-organize`：不移动文件、不建鸟种/星级目录；
- `--metadata-mode none`：不写 EXIF/XMP。**2026-08-25 起已是全局默认**
  （`advanced_config.py` DEFAULT_CONFIG 与用户配置均为 `none`），通常可省略；
  需要 Lightroom 互操作（在 LR 里看星级/鸟名关键词）时用
  `--metadata-mode embedded`（或 `sidecar`）临时改回，或在设置中心改；
- `--auto-identify`（或 `-i`）：开启识鸟（CLI 默认关，**不读 GUI 配置**）；
- `--burst`：连拍检测（CLI 默认读 GUI 配置 `burst_check`）。

> **默认改为 none 的原因（2026-08-25 决策）**：作者不用 Lightroom，
> 评星/鸟种结果以 `.superpicky/meta/*.json` + `report.db` 为唯一出口；
> EXIF/XMP 写入在 NAS 上极慢——大 JPG 原位重写 >5s/张，曾按 64 张/批
> ×5s/张的预算触发批量超时（`exiftool_manager.py` batch timeout）循环。
> `none` 模式完全跳过 ExifTool 写入，批处理尾段提速显著。

星级最终落在 JSON 的 `processing.rating`（-1/0/1/2/3），
鸟种在 `processing.species_main` 与 `detections[]`。

重置目录（恢复平铺、清 EXIF/XMP/`.superpicky`）：

```bash
.venv/Scripts/python.exe superpicky_cli.py reset <目录> -y
```

注意：reset 会删除 App 生成的预览缓存（`.superpicky/cache`）与 XMP 侧车，
属于预期行为；相机原始文件不受影响。

## 四、重要边界与已知限制 / Boundaries & Known Limitations

1. **批 = 目录**：`process` 只扫目录第一层（`_scan_files` 用 `os.listdir`）；
   `batch` 对每个子目录独立处理（各自配额池、各自聚类、各自 report.db）。
   **两个相机的照片放在不同子文件夹时，跨相机的重复照片不会去重**，
   星级也不可比。正确做法：合并到同一个平铺文件夹再处理。
2. **人工改鸟种**（GUI 结果浏览器）：照片在连拍组内会整组联动更新 DB；
   未分组的相似照不联动，错标会留在统计里。相似簇的 id 未持久化，
   因此**簇内纠错传播目前不可用**（将来若需要，须把簇写入 DB）。
3. 改鸟种时 XMP 的鸟种元数据不同步重写（只更新 DB + 移动文件）。
4. 统计代码（`report_db.get_statistics`）不分星级；
   "只统计 ≥2★"需在结果浏览器用星级过滤器实现。
5. ExifTool 时间戳读取超时已放宽到 `max(300, n/2)` 秒
   （867 张曾按旧公式 86s 超时导致连拍检测静默失败）。
